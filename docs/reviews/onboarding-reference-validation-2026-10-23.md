## Regression evidence

The baseline onboarding suite passed before implementation; the optional
selected-platform integration was initially skipped. New map/inventory tests
then failed (four failures and one error) before their implementation. Missing
semantic seeds also failed delivery tests before the bundle was installed.

Exercising the emitted reference tools exposed additional failures:

| Failure observed | Correction and regression evidence |
| --- | --- |
| Level generation indexed `content_level["via"]` for a coarser dimension source; VIBEDATA 1.4 permits own-level content without `via`. | Use the containing dimension for that case. The emitted CLI generates its membership query, and `--check` rejects stale output. |
| Standalone example declared two metrics without suppliers. | Bind both to their existing physical columns. `suppliers` now passes for both examples. |
| Four example metrics lacked the rollup declaration required by the authoring contract. | Add `SUM` for additive totals and `NON_ADDITIVE` for computed measures. The new regression first reported all four omissions, then passed. |
| A same-named field from an earlier dataset hid a missing customer-dimension supplier. | Check fields against dataset-local suppliers. The negative CLI regression first returned exit 0, then correctly returned exit 1 naming `customer.customer_key`. |
| A model whose every payload claimed extension version 0.0 passed validation. | Pin all four schema payload shapes and the checker to supported version 1.4; the new CLI regression failed before the fix and passes after it. |
| A repeated `produces` table in a single source passed the portable checker, although the shared schema rejects it. | Reject duplicate entries in the shared helper. The added regression failed before this correction. |
| Lowercase `skill.md` seed filenames were discovered as `SKILL.md` on case-insensitive macOS. | Use `convention.md`, renamed only on customer installation. The existing package-discovery test passes. |
| Native map checks in the synthetic integration could not find the emitted shared checker. | Emit `.agents/checks/validate_context.py` in that fixture and register the real runner/source membership. The real integration now passes. |
| Running seed tools locally left ignored bytecode that the existing generic-template scan tried to decode as text. | Restrict that scan to source artifacts by excluding `__pycache__`; the observed Unicode error is gone. Emitted semantic fixtures also omit generated bytecode. |
| Coverage could not report a dynamically imported checker after its temporary tree was removed. | Attribute identical fixture bytes to the retained source in the unit-test loader. The coverage report completes. The integration still loads the actual emitted file. |

## Application probes

Fresh agents read the named package entrypoint and reached supporting files,
without audit notes, tests, plans or the reference repository. They made no
customer edits, installs, warehouse calls or runtime lifecycle calls. The initial
baseline found no canonical creation/maintenance contract, no runner/shared-schema
contract and only a post-build renamed-copy check.

Three treatment scenarios exercised the new contract:

| Scenario | Observed application and review feedback |
| --- | --- |
| Existing gold fact/dimension/filtered aggregate; two ingestion sources share a dataset; external Airflow; no warehouse | Retrieved both complete semantic seeds, whole-star partitioning, matching filtered metrics, derived ratios, source `produces`, external `location`/`runs`, all five gates, and the empty-repo/first-mart exception. Did not claim data or runtime verification. |
| Refresh with a custom model glob, closed native maps, custom ADR IDs, human-edited skills and changed key/grain/billable rule | Preserved paths, schemas, ownership and history; identified stale bindings, SQL review, full-directory checks and unrun data evidence. Rejected an unsupported pass based on unread SQL or overwritten human edits. |
| Untouched renamed DuckDB sandbox with broken inherited views and truncated inventory, under pressure to build first | Required read-only all-view binding before writes, retained failed and unchecked coverage, separated rebuilt-copy portability and persistent Domain state, and kept the unsupported Studio lifecycle gate. |

The semantic/refresh probes found reachable prose conflicts. The final text now
uses metric/query-relative aggregate eligibility, reruns all mapped gates after fixes,
and asks for rulings only when meaning is ambiguous. It also makes native map
equivalents explicit and includes unmatched non-null keys and additional join
predicates in inner-join row loss. Custom ADR note-link limits remain explicit.
Independent review further retained the query-filter rule: query and metric
filters together must imply the source content filter; a narrower source cannot
answer an unrestricted wider query. The probes precede those final wording corrections; the independent whole-change
review checks the corrected text. These are application/retrieval probes, not
live Claude/Codex discovery, compaction or Studio acceptance evidence.

Repeatable scenarios are stored in `tests/onboarding/reference-refresh.json`.
