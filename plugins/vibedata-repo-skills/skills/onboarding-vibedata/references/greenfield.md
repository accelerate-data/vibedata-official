# Empty implementations

1. Confirm the data platform. The stack is dbt/dlt; ask only for the adapter/destination and non-derivable conventions. Preserve a selected package manager. If the platform is pending, complete platform-independent context and list dependent configuration as blocked.
2. Read the [scaffold recipe](../templates/greenfield/README.md). Verify current package versions, adapter/destination initialization and compatibility through the operator's approved sources before writing SDK-dependent files. Use Microsoft Learn for Microsoft products, official OpenAI documentation for OpenAI, and Context7 followed by official documentation for third-party packages. Record URLs and verified versions in the report.
3. When no convention exists, use `ingestion/`, `transformation/`, `orchestration/`, `tests/`, `requirements.txt` and `requirements-dev.txt`. Put starter source/pipeline/model files under a templates directory outside active dbt model paths. No real source definition means no registered source, business model, invented vocabulary or empty numbered ADR.
4. Add only checks that actually exist. Copy the portable context checker into `.agents/checks/` when no suitable check exists; register its root-relative command. Retain the existing checker if customer-owned. If generating pytest configuration, set `tmp_path_retention_count = 0` and `tmp_path_retention_policy = "failed"`.
5. Verify structural context, parse scaffold configuration with the selected tool if installed, and exercise synthetic examples only in a disposable local target. Label empty parses as scaffold checks; they do not verify business tests or warehouse execution. Keep unmet environment requirements explicit.

Choose defaults only where the repository and user supply none. Every selected convention must be demonstrated by the actual scaffold or marked as a convention for future work. A successful local example does not verify an unavailable customer platform.
